- (decision) [ADOPTED] Backend uses a NestJS modular monolith organized by vertical domain ownership; this prevents distributed transaction and cross-controller coupling in tenant authorization and finance ledger.
- (decision) [ADOPTED] Admin/Staff, Parent and Ops are separate frontend apps; only generated REST contracts and stateless UI primitives may be shared, preventing cross-audience session/cache/business-rule coupling.
- (decision) [ADOPTED] Production deployment uses a VPS Docker Compose topology: reverse proxy terminates TLS and routes fixed portal hosts to independently deployable static portal containers and the API.
- (decision) [ADOPTED] PostgreSQL runs in the production Compose stack on a durable VPS volume; encrypted offsite backups and a successful restore drill are mandatory production gates, preventing single-host data loss.
- (constraint) [ADOPTED] PRD final and approved replan bind clean-break, School tenant root, UserIdentity/Membership/RoleGrant authorization, fixed portal hosts, append-only finance ledger, API-owned state, and release-blocking tenant/ledger verification.
- (decision) [ADOPTED] School is the mandatory tenant root: every business aggregate, query, uniqueness rule, audit and operation is school-scoped and server verifies active membership/capability per request.
- (decision) [ADOPTED] UserIdentity is global and session payload is minimal; SchoolMembership and SchoolRoleGrant are resolved per request, while ParentProfile access derives only from active StudentParent links.
- (decision) [ADOPTED] Each portal has fixed host, OAuth callback, audience, allowlist and host-only cookie; portal sessions cannot authenticate another audience and Parent protected state is memory-only.
- (decision) [ADOPTED] API module ownership is vertical: identity/schools/memberships/authorization control access; roster/settings/finance/attendance/parent-portal own their domains; services use narrow exports, never controllers.
- (decision) [ADOPTED] Finance is append-only ledger: Invoice is immutable after issue, settlement is derived from Receipt/Allocation/Prepayment/Reversal/Refund, and payment instruction uses only issue snapshot.
- (decision) [ADOPTED] Server owns policy evaluation, VND BIGINT calculation, state transitions and snapshots; browser apps consume REST contracts and cannot calculate authoritative totals, states or access.
- (decision) [ADOPTED] High-impact mutations are transactional, use UUID Idempotency-Key and school-plus-actor-scoped Operations; timeout recovery always reconciles operation before retry.
- (decision) [ADOPTED] Prisma schema, migrations and resettable seed are clean-break target only; do not preserve legacy Admin, template invoice or dual finance schema/API/UI.
- (decision) [ADOPTED] Verification uses API unit tests, isolated PostgreSQL integration tests and portal E2E; tenant isolation, authorization revoke, ledger concurrency and operation idempotency block release.
- (decision) [ADOPTED] Parent routes use ParentSchoolContext with /api/parent/schools/:schoolId, atomic ParentProfile binding/reassignment and server-side retention; Parent PWA never caches protected responses.
- (decision) [ADOPTED] Finance owns CollectionRun lifecycle and one concurrency-safe settlement posting boundary; attendance contributes immutable eligibility sources and Finance idempotently materializes source-linked adjustments.
- (decision) [ADOPTED] Tenant graph uses composite integrity checks, roster snapshots use Asia/Ho_Chi_Minh effective intervals, attendance evidence is capability-scoped and deleted after two calendar months.
- (decision) [ADOPTED] Compose deployment uses migration expand/backfill/contract, image digests, readiness and audience smoke tests; incompatible changes require coordinated maintenance release.
- (decision) [ADOPTED] School suspension is enforced on every school-scoped request; Parent retention is 30 days for operational data after endedOn and default 12 months post-settlement finance policy.
- (decision) [ADOPTED] Finance is SchoolYear-bound with no automatic debt carryover; DebtTransfer is atomic, reversal mode has separation of duties, and leave eligibility materialization excludes holidays/PRESENT conflicts.
- (decision) [ADOPTED] Attendance creates a minimal idempotent in-app Parent notification, re-authorized at delivery, with no evidence content or external delivery channel.
- (decision) [ADOPTED] Approved long leave excludes future CollectionRun eligibility and routes issued obligations through source-linked adjustment/refund; Saturday MANUAL charges validate active service coverage to prevent duplicate charging.
- (decision) [ADOPTED] VPS production envelope is 99.5% monthly availability, RPO 24h, RTO 4h, encrypted daily offsite backups retained 35 days, quarterly restore drill, stated performance targets and audience rate limits.
