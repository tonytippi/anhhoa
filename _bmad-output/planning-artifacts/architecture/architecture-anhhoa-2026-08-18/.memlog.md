- (decision) Use a new full-stack monorepo with apps/web as React/Vite PWA and apps/api as NestJS with Prisma, backed by PostgreSQL; selectively reuse Google OAuth and VietQR logic from Grapeseed rather than its domain model.
- (decision) Deployment and hosting topology are deferred because the owner will choose and operate them independently; application configuration must remain environment-driven.
- (decision) Use a pnpm workspace with Turborepo, Node.js 22 LTS, TypeScript strict, ESLint, and Prettier; apps/web is React 19/Vite/PWA and apps/api is NestJS.
- (decision) API owns Prisma schema, migrations, domain rules, VietQR content, and audit; web uses REST JSON with React Query and has no database access; Nest modules are auth, admins, classes, students, invoice-template, invoices, bank-accounts, and reports.
- (decision) Use Prisma 7 GA migrations with PostgreSQL BIGINT integer VND amounts represented as safe JavaScript JSON numbers; database enforces invoice snapshots and unique studentId plus billingMonth.
- (decision) Use API unit tests for business rules and PostgreSQL-backed integration tests for batch creation, class transfers, invoice state transitions, snapshots, and idempotent completion; add Playwright for primary web flows after UI exists.
- (decision) Google OAuth is handled by the API, which stores session JWTs in Secure httpOnly SameSite=Lax cookies; web reads current identity from /auth/me and never stores tokens in browser JavaScript.
- (decision) REST JSON routes are domain-oriented under auth, classes, students, invoice-template, invoices, bank-accounts, and reports; API DTO validation is authoritative and frontend validation is advisory.
- (decision) Cookie-authenticated API mutations use configured origin/CORS rules plus double-submit CSRF protection; OAuth redirects are allowlisted.
- (decision) Batch invoice eligibility preview is API-owned and returns eligible plus categorized skipped counts before creation.
- (decision) High-impact idempotency uses an Admin-and-route-scoped UUID key, fingerprint, stored response, conflict on mismatched replay, and operation-status lookup for timeout reconciliation.
- (decision) Invoice state transitions enforce positive total and valid transfer account before PENDING, only PENDING can complete, and reports aggregate completed invoice payment snapshots rather than mutable account data.
- (decision) The client-generated idempotency UUID is also the operation ID, retained before submission and accepted by authenticated GET /operations/:operationId so timeout reconciliation can always begin.
