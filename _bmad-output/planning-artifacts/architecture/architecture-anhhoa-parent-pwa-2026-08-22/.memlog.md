- (constraint) Inherit Admin spine AD-1 through AD-11 as read-only: pnpm/Turborepo app boundary, API ownership, Nest dependency direction, cookie auth, REST validation, VND/UUID/date format, invoice lifecycle/snapshots, retained records, idempotency, reports and verification.
- (decision) Extend the layered modular monolith with apps/parent-web as a separate React/Vite PWA; parent-web communicates only through REST to apps/api and shares neither frontend/router/session nor business endpoints with apps/web.
- (decision) Add parents, parent-auth and parent-portal Nest modules; parent-portal exposes authorized read models and may use narrowly exported invoices/students query services but never controllers; parent-auth owns Parent OAuth/session.
- (decision) Model Parent and StudentParent as retained status-bearing data; Parent identity binds verified normalized Google email to immutable Google subject at first login, and changed subject/email reassignment is denied until Admin revoke/regrant.
- (decision) Use separate Parent OAuth callback, cookie and configured parent origin; server evaluates Parent and StudentParent status on every Parent request, and all Parent cookie mutations require origin validation, double-submit CSRF and idempotency when retryable or bulk.
- (decision) Parent portal exposes only namespaced /api/parent REST read endpoints and never reuses Admin business endpoints; invoice lists/details expose PENDING and COMPLETED only, and payment endpoint exposes snapshot data only for authorized PENDING TRANSFER invoices.
- (decision) Parent PWA persists no protected responses in the service-worker cache; it clears protected state on logout/401 and revalidates on focus, foreground and before protected views so server denial after revoke clears the UI.
- (decision) VietQR/download/deep-link payment data is derived exclusively from locked invoice payment snapshots; bank deep-link templates live in server versioned configuration, supported matrix deferred, and payment actions cannot mutate invoices.
- (decision) Preserve inherited invoice lifecycle exactly: PENDING can return to DRAFT or complete; Parent portal exposes only invoices currently PENDING or COMPLETED.
- (decision) PostgreSQL enforces unique parentId/studentId; StudentParent has ACTIVE and REVOKED, grant creates/reactivates and revoke transitions ACTIVE to REVOKED only.
- (decision) Parent OAuth state is random, browser/callback-bound, single-use and expiring; no Parent cookie is issued until identity and active-link checks pass.
- (decision) TRANSFER DRAFT-to-PENDING validates and locks total, bank, account, holder, transfer content and student/class display fields; all Parent payment guidance consumes only this snapshot.
