## Findings

### Architecture và kiểm tra xuyên story

1. **Chấp nhận deployment cross-site dù session không thể hoạt động.**
   - Nguồn: `apps/api/src/common/config/auth-config.ts:59-93`, `apps/api/src/modules/auth/auth.controller.ts:22-25,47-50`, `apps/api/src/common/middleware/csrf.middleware.ts:11-16`.
   - Điều kiện: `WEB_ORIGIN` và API origin thuộc hai schemeful site khác nhau, ví dụ `https://admin.anhhoa.vn` và `https://api.example.net`. Configuration validation chấp nhận tổ hợp này trong khi session và CSRF cookie đều dùng `SameSite=Lax`.
   - Hệ quả: OAuth có thể trông như hoàn tất nhưng browser không gửi cookie trong credentialed cross-site request; `/auth/me` không xác thực được và mutation không thể qua CSRF validation.
   - Hướng xử lý: **sửa ngay**. Bắt buộc API/web cùng site khi load auth configuration, suy ra API origin từ public configuration rõ ràng hoặc callback URL, đồng thời thêm coverage ở config và browser. Phòng ngừa từ gốc là test auth deployment invariant thay vì chấp nhận tùy ý CORS origin như một topology có thể deploy.

### Aggregate views

- Architecture delta: hướng dependency giữ đúng spine: web dùng credentialed REST identity, API sở hữu OAuth, cookie, guard, Prisma và Admin persistence. Không phát hiện cycle hoặc dependency từ web đến database trong các file Epic 1 đã kiểm tra.
- Duplication và size: range không có merge commit. Thay đổi source lớn nhất được tách hợp lý giữa typed auth configuration, auth guard/controller và web identity bootstrap; không phát hiện implementation trùng lặp thêm trong phạm vi kiểm tra.
- Spec reconciliation: implementation đáp ứng shell, allowlist, cookie, CSRF, protected-route và PWA contract đã công bố. Lỗ hổng cross-site configuration ở trên khiến hành vi session với valid config không đúng tổng quát, nên là defect chứ không phải thay đổi spec.
